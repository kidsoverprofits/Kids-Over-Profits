**Rules the map keeps, and where they live:**

- *Never drop a name that is on the stage.* `applyLayout` in
  `js/network-map/focus.js` picks the zoom by asking the renderer
  (`renderer.dropsAt` in `canvas.js`, a dry run of the label pass) how
  many on-stage names a zoom would drop, and takes the lowest zoom with
  none. Do not replace this with an estimate: an estimated floor with a
  margin was tried first and dropped 16 of 60 names once the years line
  existed. A node may only be off the stage when framing everything would
  drop names; the module tests check that against the renderer.
- *An owner brings only itself* (the owner's decision); a node with
  connections that are not on the board shows "+N" instead.
- The board is no longer the whole roster: `addPeople` in the build adds a
  person tied to two or more nodes, or named founder, owner, CEO or
  president of one (see "People the board does not have").

## How to work in this repo

- **The checkout at `C:\Users\daniu\source\repos\Kids-Over-Profits` is
  shared** with other sessions. Its working files often differ from its
  branch only because work landed on main from elsewhere. Do not commit
  from it blindly, and never `reset --hard` or stash in it.
- **What worked all day for landing a change:** `git worktree add -f
  <scratchpad>/wt-x -b tmp/x origin/main`, copy in only your files, run the
  tests there, check `git diff --unified=0 | grep '^-'` shows only your
  own removed lines (a copied file can silently revert another session's
  commit), commit, `git push origin tmp/x:main`, then remove the worktree
  and branch. Rebase on origin/main if the push is rejected. Do not
  remove the worktree before the push has succeeded: one push was rejected
  after its worktree was gone, and the commit had to be recovered by SHA.
- **Deploys:** every push to main deploys by `.github/workflows/deploy.yml`
  (`gh run list --workflow=deploy.yml`). Verify by fetching a static asset
  with a browser user agent; HTML pages are bot-walled from outside, but
  a server-side curl over SSH renders them.
- **The Bash tool collapses backslashes.** Edits containing regexes (`\b`,
  `\d`) came out as control characters when passed through a heredoc.
  Write a Python patch file with the Write tool and run it, or use the
  Edit tool. Files mix CRLF and LF; preserve whichever a file uses.
- **Local PHP:** there is no php on PATH; use Local's
  `lightning-services/php-8.2.*/bin/win64/php.exe` with `-n -l` to lint,
  and add `-d extension_dir=... -d extension=pdo_sqlite` for the harnesses.
- **Production reads:** SSH and the prod SQLite mirror are described in
  the auto-memory (`prod-ssh-db-access`, `prod-sqlite-mirror`). Reads are
  fine; ask before any write to production.
